8.1 pathfind 工具

功能简介

#! /bin/sh -
#
# 在查找路径下寻找一个或多个原始文件或文件模式，
# 查找路径乃由特定的环境变量所定义。
#
# 标准输出所产生的结果，通常是查找路径下找到的每个文件之第一个实体的完整路径，
# 或是“filename：notfound”的标准错误输出。
#
# 如果所有文件都找到，则退出码为0，
# 否则，即为找不到的文件个数（非0）
# （Shell的退出码限制为125）
#
# 语法：
# pathfind [--all] [--?] [--help] [--version] envvar pattern(s)
#
# 使用--all选项时，在路径下的每个目录都会被查找，
# 而非停在第一个找到者。
IFS='
'  
OLDPATH="$PATH"
PATH=/bin:/usr/bin
export PATH
error()
{
    echo "$@" 1>&2
    usage_and_exit 1
}
usage()
{
    echo "Usage: $PROGRAM [--all] [--?] [--help] [--version] envvar pattern(s)"
}
usage_and_exit()
{
    usage
    exit $1
}
version()
{
    echo "$PROGRAM version $VERSION"
}
warning()
{
    echo "$@" 1>&2
    EXITCODE=`expr $EXITCODE + 1`
}
all=no
envvar=
EXITCODE=0
PROGRAM=`basename $0`
VERSION=1.0
while test $# -gt 0
do
    case $1 in
    --all | --al | --a | -all | -al | -a )
        all=yes
        ;;
    --help | --hel | --he | --h | '--?' | -help | -hel | -he | -h | '-?' )
        usage_and_exit 0
        ;;
    --version | --versio | --versi | --vers | --ver | --ve | --v |
    -version | -versio | -versi | -vers | -ver | -ve | -v )
        version
        exit 0
        ;;
    -*)
        error "Unrecognized option: $1"
        ;;
    *)
        break
        ;;
    esac
    shift
done
envvar="$1"
test $# -gt 0 && shift
test "x$envvar" = "xPATH" && envvar=OLDPATH
dirpath=`eval echo '"$'$envvar'"' 2>/dev/null | tr : ' '`
# 为错误情况进行健全检测
if test -z "$envvar"
then
    error Environment variable missing or empty
elif test "x$dirpath" = "x$envvar"
then
    error "Broken sh on this platform: cannot expand $envvar"
elif test -z "$dirpath"
then
    error Empty directory search path
elif test $# -eq 0
then
    exit 0
fi
for pattern in "$@"
do
    result=
    for dir in $dirpath
    do
        for file in $dir/$pattern
        do
            if test -f "$file"
            then
                result="$file"
                echo $file
                test "$all" = "no" && break 2
            fi
        done
    done
    test -z "$result" && warning "$pattern: not found"
done
test $EXITCODE -gt 125 && EXITCODE=125
exit $EXITCODE

⑤eval 处理动态获取环境变量的值【难点】

需求：变量envvar里面存的是环境变量的名字字符串，例如envvar="PATH"，想要拿到$PATH的值。

1

dirpath=`eval echo '"$'$envvar'"' 2>/dev/null | tr : ' '`

拆解：

  1. 拼接出字符串 echo "$PATH"，交给eval二次解析执行；
  2. eval执行后输出PATH内容，例如/bin:/usr/bin:/home/bin；
  3. 管道交给tr : ' '，把冒号分隔的路径列表，替换成空格分隔。

eval：对字符串完整再跑一整套shell解析流程；功能强大，但容易引入安全风险，谨慎使用。

eval命令详解

eval 到底是什么

eval 是 shell 特殊内建命令。

一句话：eval 接收一串字符串，把这串字符串，再完整重新做一遍全套shell解析，然后执行解析完得到的命令。

普通命令：shell只解析一次就执行。 eval：先正常解析一遍拿到文本，再把文本交给shell再完整解析第二轮，然后运行。

重点：eval本身不会生成echo，echo是字符串里本来就有的命令；eval只是把拼装出来的字符串当命令跑一遍。

简单小例子理解

示例1

1
2

cmd="echo hello"
$cmd
  • shell第一轮解析：$cmd替换成字符串 echo hello
  • 普通执行：把echo hello当成1个单词，试图找名叫echo hello的程序，找不到，报错。
1
2

cmd="echo hello"
eval $cmd
  1. 第一轮shell解析：$cmd替换得到文本：echo hello
  2. eval登场：把这串文本，重新交给shell，再完整解析一次
  3. 第二轮解析：分词，识别命令echo，参数hello
  4. 执行 echo hello，输出hello。

👉 eval的能力就是：二次解析字符串，把字符串变成真正可执行的命令行。

回到pathfind那行：eval echo '"$'$envvar'"'

假设 envvar=PATH

第一步：shell第一轮解析（eval还没干活）

原始代码片段：

1

eval echo '"$'$envvar'"'

shell先做变量替换：$envvar替换为PATH。 传给eval的参数字符串变成：

1

echo "$PATH"

⚠此时这还只是一堆文本字符串，并没有执行echo，只是字符串内容长得像一条命令。

第二步：eval接手

eval拿到字符串 echo "$PATH"，把这一整段当做新的命令行，完整重新解析、执行。 于是shell识别出：

  • 命令：echo
  • 参数："$PATH"，再解析变量$PATH，取出PATH环境变量的值。

于是就执行了 echo "/bin:/usr/bin:..."，打印出PATH的内容。

❗eval并不会凭空创造echo；echo是我们拼接出来的字符串里面写死的；eval只是负责把字符串翻译成真正命令执行。

对比：不加eval会发生什么？

1

echo '"$'$envvar'"'

envvar=PATH，第一轮替换后得到参数："$PATH" 直接执行echo，只是原样打印字面文本：

1

"$PATH"

不会展开PATH变量！因为只解析了一轮，双引号只是普通字符串字符，不会触发变量展开。

eval工作流程图

普通命令：

源代码 → shell【一次解析】 → 执行命令

eval命令：

源代码 → shell【第一轮解析，得到字符串文本】 → eval把文本丢回shell【第二轮完整解析】 → 执行最终命令

⚠eval巨大的风险（重点）

因为eval会二次解析任意字符串，如果字符串内容来自用户外部不可信输入，会造成shell注入漏洞。

危险示范：

1
2

var=';rm -rf $HOME'
eval "echo $var"

经过eval二次解析，;会被识别成分隔多条命令，rm就会被执行！

pathfind脚本里面eval是安全的：envvar来自脚本自己解析的命令行参数，做过控制，不受外部恶意注入。

总结

  1. eval 是shell特殊内建，功能：对输入的字符串，再完整执行一遍shell解析流程，之后运行得到的命令。
  2. eval不会产生新命令，字符串里面写什么，第二轮就执行什么；pathfind例子中字符串里写了echo，所以eval就会执行echo。
  3. 普通代码只会解析一轮；eval多一轮解析，这也是它强大同时危险的根源。
  4. 风险：不要把不受信任的外部输入交给eval，会命令注入。

记忆口诀： eval = 把字符串，再当一行命令重新解析跑一次。

$#与$@区别

把两个点讲清楚

$# 数字：参数的总个数
"$@" 全部位置参数「内容」，是一整组参数列表，不是数字！

先回顾 pathfind 这几行关键代码：

1
2
3
4

envvar="$1"
test $# -gt 0 && shift   # ←这里执行了shift！
# ……后面才是
for pattern in "$@"

调用示例：

1

pathfind PATH ls gcc

调用这条命令时，脚本刚启动那一刻：

  • $1 = PATH
  • $2 = ls
  • $3 = gcc
  • $# = 3 （一共3个参数，这是数字）
  • "$@" = "PATH" "ls" "gcc" （全部参数的内容）

第一步：envvar="$1"

1

envvar="$1"

把第一个参数 $1（也就是PATH）存到变量envvar。

此时位置参数还没变：$1=PATH，$2=ls，$3=gcc

第二步：test $# -gt 0 && shift

执行了 shift！ shift 的作用：丢掉 $1，后面参数整体往前挪一位。

shift执行之后状态发生变化：

  • $1 现在变成原来的$2 → ls
  • $2 现在变成原来的$3 → gcc
  • $# 从 3 变成 2（参数个数，数字）
  • "$@" 现在变成："ls" "gcc"

shift把原来第一个参数PATH从位置参数列表里扔掉了，所以后面 "$@" 里面就不再包含 PATH！

PATH并没有消失，它已经提前保存到变量envvar里面留着用了，不再需要留在位置参数里。

分清极易混淆的两个特殊变量

特殊变量 是什么 示例（调用pathfind PATH ls gcc刚启动时）
$# 数字，代表参数有多少个 3，仅仅是数字，没有字符串内容
"$@" 全部位置参数的内容列表 "PATH" "ls" "gcc"，是一串参数，不是数字

💡记忆： # 像计数的井号 → 数个数（数字）
@ 代表“全部、每一个”，代表参数内容集合。

all=no        # 正确赋值，=左右不能空格
all = no      # 错误！shell会把all识别成命令，试图运行命令 all，参数是= no

赋值语法：VAR=value

  • =紧贴左右，不能有空格。
  • 如果加空格，shell把第一个单词当做命令名；all被当成要执行的外部命令。

2、test 字符串比较：test 字符串1 = 字符串2，=两边必须空格

1
2

test "$all" = "no"     # 正确，=两边空格
test "$all"="no"       # 错误！没有空格

为什么 test "$all"="no" 是错的？

test 是一个命令（内建命令），它接收多个参数。

1
2

test  "$all"  =  "no"
#     arg1    arg2 arg3
  • 参数1："$all"
  • 参数2：=
  • 参数3："no"

test依靠这3个参数识别：做字符串相等比较。

如果写：test "$all"="no" shell只会传给test一个参数："no=no"（拼接后的一整个字符串）。 test拿到单个字符串，规则：字符串非空就返回true，判断逻辑完全失效，永远为真！

[ "$all" = "no" ] 和test一样，[也是shell内建命令，]是最后一个参数，=两边同样必须空格。[和test命令等价的，都是测试字符串。唯一区别是[需要一个]结束。

1
2

[ "$all" = "no" ]   # ✅
[ "$all"="no" ]     # ❌

3、还有一种：==，在不同场景

  1. POSIX test / [ ]：只用单个=做字符串相等；== 部分sh不支持，尽量不要用。
  2. bash的双中括号 [[ "$a" == "$b" ]]：可以用==，两边也要空格。

4、还有哪些地方=不能加空格？

① 变量导出赋值

1
2

export ALL=no     # ✅无空格
export ALL = no   # ❌报错

② 算术赋值 $(( )) 内部

$(( ... )) 算术上下文，赋值 = 两边不要空格；比较 ==两边要有空格

1
2

a=$((b=10))        # ✅赋值，=无空格
a=$(( b == 10 ))   # ✅比较，==两边空格

③ case 语句，)前面的等号不是运算符，属于模式，不受这套规则影响

汇总表格

场景 写法要求 示例
普通变量赋值 =两边不能有空格 all=no ✅；all = no ❌
export赋值 =两边不能有空格 export all=no ✅
test / [ ] 字符串相等比较 =两边必须有空格 test "$all" = "no" ✅；test "$all"="no" ❌

拆解：

  1. test 是命令；"$all"、=、"no" 是传给test的3个独立参数，=左右必须空格。

# shebang：指定使用POSIX sh解释器；- 安全选项，禁止欺骗脚本

# build-all [--?]

# [--all "..."]

# [--cd "..."]

# [--check "..."]

# [--configure "..."]

# [--environment "..."]

# [--help]

# [--logdirectory dir]

# [--on "[user@]host[:dir][,envfile] ..."]

# [--source "dir ..."]

# [--userhosts "file(s)"]

# [--version]

# package(s)

#

# 可选用的初始化文件

# $HOME/.build/directories    源码搜索目录列表

# $HOME/.build/userhosts      远程主机列表 [user@]host[:dir][,envfile]

# 重置IFS恢复默认：空格、tab、换行，抵御IFS环境变量注入攻击

IFS='
'

# 重置PATH，只保留系统可信目录，防止恶意同名程序劫持

PATH=/usr/local/bin:/bin:/usr/bin

##############################################################################

# 函数 build_one：处理单台远程主机完整构建流程

# 入参示例 $1 = jones@freebsd.example.com:/local/build,$HOME/.build/c99

##############################################################################
build_one() {
    # 语法：
    #   build_one [user@]host[:build‑directory][,envfile]

    # arg="`eval echo $1`"
    # $1输入：jones@freebsd.example.com:/local/build,$HOME/.build/c99
    # eval会展开$HOME，执行echo，得到arg=jones@freebsd.example.com:/local/build,/home/jones/.build/c99
    arg="`eval echo $1`"

    # userhost="`echo $arg | sed -e 's/:.*//'`"
    # sed：把第一个冒号以及后面全部删掉
    # arg=jones@freebsd.example.com:/local/build,xxx
    # 结果 userhost=jones@freebsd.example.com
    userhost="`echo $arg | sed -e 's/:.*//'`"

    # user="`echo $userhost | sed -e 's/@.*//'`"
    # sed：把@以及后面全部删掉
    # userhost=jones@freebsd.example.com
    # 结果 user=jones
    user="`echo $userhost | sed -e 's/@.*//'`"

    # test "$user" = "$userhost" && user=$USER
    # 判断：如果没有@符号（user等于userhost），说明没有指定用户名，则取当前本地登录用户$USER
    # 例：userhost=freebsd.example.com，则user=freebsd.example.com，条件成立 user=$USER
    test "$user" = "$userhost" && user=$USER

    # host="`echo $userhost | sed -e 's/^[^@]*@//'`"
    # sed：删除从开头到@的全部字符；拿到主机名
    # userhost=jones@freebsd.example.com
    # 结果 host=freebsd.example.com
    host="`echo $userhost | sed -e 's/^[^@]*@//'`"

    # envfile="`echo $arg | sed -e 's/^[^,]*,//'`"
    # sed：删除开头直到第一个逗号；取逗号后面的环境配置文件路径
    # arg=jones@freebsd.example.com:/local/build,$HOME/.build/c99
    # 结果 envfile=/home/jones/.build/c99
    envfile="`echo $arg | sed -e 's/^[^,]*,//'`"

    # test "$envfile" = "$arg" && envfile=/dev/null
    # 判断：如果字符串没变=没有逗号，代表没有传入envfile，设置为/dev/null空文件
    test "$envfile" = "$arg" && envfile=/dev/null

    # builddir="`echo $arg | sed -e 's/^.*://' -e 's/,.*//'`"
    # 两个sed：①删除开头到冒号；②删除逗号以及后面；拿到远程构建目录
    # arg=jones@freebsd.example.com:/local/build,$HOME/.build/c99
    # 结果 builddir=/local/build
    builddir="`echo $arg | sed -e 's/^.*://' -e 's/,.*//'`"

    # test "$builddir" = "$arg" && builddir=/tmp
    # 判断：没有冒号，未指定构建目录，默认使用/tmp
    test "$builddir" = "$arg" && builddir=/tmp

    # parbase=`basename $PARFILE`
    # basename：去掉路径，只取文件名
    # PARFILE=/home/src/gcc‑12.2.tar.gz → parbase=gcc‑12.2.tar.gz
    parbase=`basename $PARFILE`

    # NB: 如果这些模式被更换过，则更新 find_package()
    # package=`echo $parbase | sed 多条替换，去掉各种压缩包后缀
    # parbase=gcc‑12.2.tar.gz → package=gcc‑12.2
    package=`echo $parbase | \
        sed -e 's/[.]jar$//' \
            -e 's/[.]tar[.]bz2$//' \
            -e 's/[.]tar[.]gz$//' \
            -e 's/[.]tar[.]Z$//' \
            -e 's/[.]tar$//' \
            -e 's/[.]tgz$//' \
            -e 's/[.]zip$//'`

    # 如果我们在远程主机上看不到包文件，则复制过去
    # 打印将要执行的ssh命令，仅日志输出，不会执行
    echo $SSH $SSHFLAGS $userhost "test -f $PARFILE"

    # if $SSH $SSHFLAGS $userhost "test -f $PARFILE"
    # ssh登录远程主机执行 test -f $PARFILE，判断该压缩包是否已经存在远程
    if $SSH $SSHFLAGS $userhost "test -f $PARFILE"
    then
        # 远程已经存在，parbaselocal直接使用远程完整路径，不需要scp上传
        parbaselocal=$PARFILE
    else
        # 远程不存在：parbaselocal只用文件名；执行scp把本地包传到远程builddir目录
        parbaselocal=$parbase
        echo $SCP $PARFILE $userhost:$builddir
        $SCP $PARFILE $userhost:$builddir
    fi

    # 在远程主机上解开存档文件、构建，及以后台执行方式检查它
    sleep 1  # 睡眠1秒，保证时间戳不同，日志文件名不会冲突
    now=`date $DATEFLAGS`          # 获取当前时间戳，例 2026.09.14.10.20.30
    logfile="$package.$host.$now.log" # 日志文件名 gcc‑12.2.freebsd.example.com.2026.09.14.10.20.30.log

    # nice $SSH ... "一大段远程shell脚本" < /dev/null > "$LOGDIR/$logfile" 2>&1 &
    # nice：降低进程优先级；
    # ssh把双引号内全部文本发送远程机器执行；
    # < /dev/null：清空ssh标准输入，防止ssh挂起等待输入；
    # >... 2>&1：标准输出、标准错误全部写入本地日志文件；
    # & 【后台运行】：build_one函数立刻返回，不等远程编译结束！
    nice $SSH $SSHFLAGS $userhost "
        echo '
        # 尝试执行远程前置钩子脚本BUILDBEGIN；兼容 .(posix) 和 source(csh/bash)；|| true保证失败不中断
        test -f $BUILDBEGIN && . $BUILDBEGIN || \
        test -f $BUILDBEGIN && source $BUILDBEGIN || \
        true;
        # 打印各种诊断信息，全部写入日志
        echo 'Package: $package'
        echo 'Archive: $PARFILE'
        echo 'Date: $now'
        echo 'Local user: $USER'
        echo 'Local host: `hostname`'
        echo 'Local log directory: $LOGDIR'
        echo 'Local log file: $logfile'
        echo 'Remote user: $user'
        echo 'Remote host: $host'
        echo 'Remote directory: $builddir'
        printf 'Remote date: '
        date $DATEFLAGS
        printf 'Remote uname: '
        uname -a || true;
        printf 'Remote gcc version: '
        gcc --version | head -n 1 || echo;
        printf 'Remote g++ version: '
        g++ --version | head -n 1 || echo;
        # 读取envfile配置，去掉注释；换行转为空格
        echo 'Configure environment: `$STRIPCOMMENTS $envfile | $JOINLINES`'
        echo 'Extra environment: $EXTRAENVIRONMENT'
        echo 'Configure directory: $CONFIGUREDIR'
        echo 'Configure flags: $CONFIGUREFLAGS'
        echo 'Make all targets: $ALLTARGETS'
        echo 'Make check targets: $CHECKTARGETS'
        echo 'Disk free report for $builddir/$package:'
        df $builddir | $INDENT
        echo 'Environment:'
        env | env LC_ALL=C sort | $INDENT
        echo '
        umask $UMASK;                                 # 设置远程机器文件掩码
        cd $builddir || exit 1;                       # 进入远程构建目录，失败直接退出远程脚本
        /bin/rm -rf $builddir/$package;               # 删除旧源码目录，保证干净构建；用绝对rm，规避别名‑i
        $PAR $parbaselocal;                           # 执行解压命令，例 tar xfz gcc‑12.2.tar.gz
        test '$parbase' = '$parbaselocal' && /bin/rm -f $parbase; # 如果是scp上传的包，解压完毕删除远程压缩包
        cd $package/$CONFIGUREDIR || exit 1;          # 进入源码构建子目录
        test -f configure && \
            chmod a+x configure && \                  # configure增加可执行权限
            env `$STRIPCOMMENTS $envfile | $JOINLINES` \ # 加载envfile内环境变量
                $EXTRAENVIRONMENT \
                nice time ./configure $CONFIGUREFLAGS ; # 执行configure配置
        nice time make $ALLTARGETS && nice time make $CHECKTARGETS ; # make编译 && make check测试
        echo '==============================' ;
        echo 'Disk free report for $builddir/$package:' ;
        df $builddir | $INDENT ;
        printf 'Remote date: ' ;
        date $DATEFLAGS ;
        cd;                                           # 切回远程用户家目录
        test -f $BUILDBEGIN && . $BUILDBEGIN || \
        test -f $BUILDBEGIN && source $BUILDBEGIN || \
        true ;
        echo '==============================' ;
    " < /dev/null > "$LOGDIR/$logfile" 2>&1 &
}

##############################################################################

# find_file函数：判断文件是否可读；找到则用全局变量PAR、PARFILE保存解压命令和文件路径

# 参数1：文件路径；参数2：解压命令字符串，如 "tar xfz"

# 返回0成功，1失败；sh函数只能返回0‑255状态；结果靠全局变量传出

##############################################################################
find_file() {
    # Usage:
    #   find_file file program‑and‑args
    # Return 0 (success) if found, 1 (failure) if not found
    if test -r "$1"        # test -r 判断文件是否存在并且可读
    then
        PAR="$2"           # 全局变量PAR保存解压命令，例 tar xfz
        PARFILE="$1"       # 全局变量PARFILE保存完整文件路径
        return 0           # return 0 函数执行成功
    else
        return 1           # return 1 文件不可读，失败
    fi
}

##############################################################################

# find_package函数：在SRCDIRS源码目录列表查找软件压缩包

# $1入参：包名，例 gcc‑12.2

# 找到后全局变量 PAR、PARFILE 赋值；找到就return退出函数

##############################################################################
find_package() {
    # Usage: find_package package‑x.y.z
    # base=`echo "$1" | sed -e 's/[-_][.]*[0‑9].*$//'`
    # sed：切掉版本号部分；输入gcc‑12.2 → base=gcc
    base=`echo "$1" | sed -e 's/[-_][.]*[0-9].*$//'`
    PAR=                     # 清空全局解压命令变量
    PARFILE=                 # 清空全局文件路径变量
    for srcdir in $SRCDIRS   # 循环遍历每一个源码搜索目录 SRCDIRS是空格分割字符串
    do
        test "$srcdir" = "." && srcdir="`pwd`" # 如果目录是点，替换成当前工作目录绝对路径
        for subdir in "$base" ""               # 优先在gcc子目录查找；找不到再直接当前目录查找
        do
            # NB: update package setting in build_one() if this list changes
            # 依次尝试各种压缩后缀；find_file找到文件，&& return 立刻退出整个函数
            find_file $srcdir/$subdir/$1.tar.gz "tar xfz" && return
            find_file $srcdir/$subdir/$1.tar.Z  "tar xfz" && return
            find_file $srcdir/$subdir/$1.tar    "tar xf"  && return
            find_file $srcdir/$subdir/$1.tar.bz2 "tar xfj" && return
            find_file $srcdir/$subdir/$1.tgz    "tar xfz" && return
            find_file $srcdir/$subdir/$1.zip    "unzip -q" && return
            find_file $srcdir/$subdir/$1.jar    "jar xf" && return
        done
    done
}

重点拆解 build_one() 函数（核心难点）

入参示例：jones@freebsd.example.com:/local/build,$HOME/.build/c99
格式规则：[用户@]主机[:远程构建目录][,环境变量配置文件]

build_one内部步骤

  1. 解析参数字符串，用sed拆分4部分：
    • user：远程用户名
    • host：远程主机名
    • builddir：远程机器工作目录，缺省/tmp
    • envfile：远程环境配置文件，缺省/dev/null
  2. 判断远程机器上是否已经存在这个源码包：
    • 如果远程已经存在：不复制；
    • 不存在：调用scp把本地压缩包传到远程。
  3. sleep 1：保证日志文件名时间戳不重复。
  4. 拼接日志文件名：包名.主机.时间.log
  5. nice $SSH ... "长shell脚本" < /dev/null >日志 2>&1 &
    • nice降低CPU优先级，不抢占交互式用户资源；
    • ssh向远程主机传递一大段多行shell代码；
    • < /dev/null：把ssh标准输入置空，防止挂起等待输入；
    • >log 2>&1：stdout、stderr全部写入本地日志；
    • 末尾 &：放到后台执行！ → 实现多台主机并行，build_one立刻返回，不会等待编译结束。

远程机器上执行的整套流程（ssh传递过去的脚本）

  1. 优先执行钩子脚本 $BUILDBEGIN；兼容. 和 source 两种shell；
  2. 打印大量诊断信息写入日志：包名、时间、gcc/g++版本、磁盘剩余、全部环境变量；
  3. umask设置权限；cd进入远程构建目录；
  4. /bin/rm -rf 删除旧构建目录，干净构建环境；
  5. 解压源码包；
  6. 加载envfile里面的编译环境变量，执行./configure；
  7. make编译、make check做测试；
  8. 打印构建结束信息，执行结束钩子脚本$BUILDEND。

坑：引号嵌套极其麻烦：一部分变量本地shell展开，另一部分传到远程主机再展开。

    msg="Check build logs for $p in `hostname`: $LOGDIR"
    echo "$msg"
    echo "$msg" | $MAIL -s "$msg" $USER 2> /dev/null

    for u in $userhosts    # 遍历每一台远程主机
    do
        build_one $u      # 启动后台构建任务，不阻塞
    done
done
# shell退出码最大125，超过截断
test $EXITCODE -gt 125 && EXITCODE=125
exit $EXITCODE

⚠关键点：build_one $u内部ssh命令带&后台运行。 脚本不会等待远程编译完成，执行完立刻退出；编译还在远程服务器跑。 如果希望脚本阻塞等待全部任务结束，脚本末尾增加一条 wait。

本章通用shell工程实践总结

脚本的工程经验

  1. 日志非常重要：记录时间、编译器版本、磁盘空间、环境变量，方便排查编译失败。
  2. 健壮性：目录不存在尝试自动创建日志目录，多位置fallback。
  3. 安全：脚本禁止root运行，远程执行/bin/rm -rf要谨慎。
  4. 可移植性兼容不同shell：同时兼容. 和source；很多操作用|| true避免命令失败直接终止整条ssh命令。
  5. 变量展开区分：哪些变量在本地shell展开，哪些在远程主机shell展开，引号处理很复杂。

小工具

  1. basename $0 获取脚本名字；dirname获取路径；
  2. break N 跳出N层循环；
  3. "x$var"技巧，避免变量为空/以‑开头干扰test；
  4. 退出码上限125，超过强制赋值125；
  5. shell函数没有返回值，复杂结果靠全局变量输出；
  6. eval慎用，用于动态解析变量名；
  7. 远程ssh批量任务可以放到后台&实现并行；需要等待则使用wait。

小结

  1. eval会完整重跑一遍shell解析流程，输入不可信的时候会产生安全漏洞。
  2. ssh传递复杂多行命令，本地和远程两层shell引号嵌套极其容易出错。
  3. 后台运行子shell，父shell拿不到子shell内变量；需要用全局变量返回结果。
